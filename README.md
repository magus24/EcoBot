# EcoBot — детекция мусорных свалок и панель оператора

Система автоматического обнаружения складированного мусора по камерам видеонаблюдения
и веб-панель для операторов, которые подтверждают или отклоняют detections.

```
камера / CCTV-канал
        │
        ▼
┌──────────────────────────────┐   YOLO    ┌───────────────────┐
│ detector/                    │ ────────► │ bounding boxes    │
│  trash_detector.py — YOLOv8n │           └───────────────────┘
│  main.py — YOLOv5 + YOLOv8n  │                  │
└──────────────────────────────┘                  │ POST /add/<area>/<mac>
                                                  ▼
                                    ┌──────────────────────────┐
                                    │ backend/ — Flask API      │
                                    │ SQLite + каталог media/   │
                                    └────────────┬─────────────┘
                                                 │ REST + Bearer token
                                                 ▼
                                    ┌──────────────────────────┐
                                    │ frontend/ — React 18      │
                                    │ Home · Verified ·        │
                                    │ Deleted · History        │
                                    └──────────────────────────┘
```

## Зачем

Уборка мусора — задача с большими трудозатратами, а дежурный оператор не может
одновременно смотреть за десятками камер. EcoBot решает три задачи:

- **детектинг** — модель находит скопления мусора в кадре и рисует bounding boxes;
- **оповещение** — detections попадают в базу и сразу появляются в панели с бейджем
  необработанных записей;
- **подтверждение** — человек верифицирует снимок: мусор действительно лежит
  (уборка нужна) или это ложное срабатывание.

## Возможности

**Детектор**

- Два независимых скрипта: быстрый COCO-детектор мусора и связка «кастомная модель
  свалок + COCO-детектор бутылок».
- Автоматический перебор бэкендов камеры (DirectShow → MSMF → default) с прогревом
  и понятной диагностикой, если камера не открылась.
- Ограничение FPS, обработка «мусорных» кадров, выход по ESC / `q`.
- Выделение объекта, ближайшего к центру кадра, и выдача его координат
  получателю (заглушка `send_to_robot()` — точка подключения серво-руки).

**API**

- Приём кадров (`multipart/form-data`), хранение в SQLite, раздача картинок.
- Авторизация по подписанному токену, пароли только в виде хеша (`werkzeug.security`).
- Параметризованные SQL-запросы — инъекции невозможны принципиально.
- Жизненный цикл detection: `0` новое → `1` подтверждено → `2` удалено,
  с возможностью откатить любое решение.
- Разделение по участкам: оператор видит только свой район, `admin` — все.

**Панель**

- Страницы Home / Verified / Deleted / History с поиском и сортировкой по дате.
- Автообновление раз в 5 секунд, счётчик необработанных detections в navbar.
- Превью кадра во вложенном окне, подтверждение и удаление в один клик.
- Адрес API задаётся переменной `REACT_APP_API_URL` — фронтенд не привязан к localhost.

## Быстрый старт

Нужны Python 3.10+, Node.js 18+ и веб-камера (для детектора).

```bash
git clone https://github.com/magus24/EcoBot.git
cd EcoBot
```

### 1. Зависимости Python

```bash
python -m venv .venv
# Windows:      .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Детектор

```bash
# COCO-детектор: bottle/cup, подсвечивает ближайший к центру объект
python detector/trash_detector.py

# Кастомная модель свалок + COCO-детектор бутылок
python detector/main.py --camera 0 --conf 0.12 --bottle-conf 0.20 --imgsz 960 --box-shrink 0.08
```

`ESC` — выход из `trash_detector.py`, `q` — из `main.py`. Если камера не открылась,
скрипт печатает причины (занята другим приложением, отключена в диспетчере
устройств, блокировка антивирусом). Путь к весам можно переопределить:
`ECOBOT_YOLO_MODEL=/path/to/model.pt`.

### 3. API

```bash
cd backend
python api.py                     # http://127.0.0.1:5000
```

Создайте первого оператора (пароль сохраняется только хешем):

```bash
python manage.py create-user admin ops@ecobot.local -p admin123
python manage.py list-users
```

### 4. Панель

```bash
cd frontend
npm install
npm start                         # http://localhost:3000
```

Войдите под `admin` / `admin123`. Чтобы указать другой адрес API:

```bash
cp .env.example .env.local        # REACT_APP_API_URL=https://api.example.com
```

### Проверка сквозного сценария

Панель станет непустой, если отправить кадр вручную:

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:5000/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | python -c "import json,sys;print(json.load(sys.stdin)['token'])")

curl -X POST http://127.0.0.1:5000/add/Gota/AA:BB:CC:DD:EE \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@path/to/frame.jpg"
```

Запись появится в Home, кнопка **Verify** переведёт её в Verified, **Delete** — в Deleted.

## Модель и датасет

Публичных датасетов со свалками нужного качества не нашлось, поэтому датасет
собран самостоятельно:

- **1000** оригинальных кадров с камер наблюдения, снятых в разное время суток;
- разметка вручную в **LabelImg** (YOLO-формат);
- аугментация: flip, rotate 90°, shear, exposure, blur, noise → **5000** изображений;
- обучение YOLOv5, лучшие веса — `models/best1000.pt` (класс `garbage`).

В репозитории также лежит `models/yolov8n.pt` — стандартная COCO-модель
Ultralytics, она используется как детектор бутылок и как быстрый демо-режим.
Общий вес моделей — около 10 МБ, поэтому они входят в репозиторий и проект
запускается сразу после клона.

Пороги уверенности подобраны под каждую модель отдельно: для свалок `0.12–0.15`
(модель слабее), для бутылок `0.20–0.25`.

## API

`area` — участок (например, `Gota`); специальное значение `admin` возвращает все записи.
`image` — имя файла, которое вернул `POST /add`.

| Метод | Путь | Токен | Назначение |
| --- | --- | :---: | --- |
| `GET` | `/health` | — | проверка живости сервиса |
| `POST` | `/users` | — | регистрация; работает только пока нет ни одного пользователя |
| `POST` | `/login` | — | `{"username","password"}` → профиль и токен |
| `GET` | `/valid/<user>/<pass>` | — | устаревший вход через URL, оставлен для совместимости |
| `DELETE` | `/users/<username>` | ✔ | удалить пользователя |
| `GET` | `/whoami` | ✔ | кто сейчас авторизован |
| `POST` | `/add/<area>/<mac>` | ✔ | загрузить кадр, поле `file` |
| `GET` | `/media/<image>` | ✔* | отдать кадр (*для `<img>` токен можно передать в query) |
| `GET` | `/fetch/<area>` | ✔ | новые detections (статус 0) |
| `GET` | `/fetchv/<area>` | ✔ | подтверждённые (статус 1) |
| `GET` | `/fetch_delete/<area>` | ✔ | удалённые (статус 2) |
| `GET` | `/fetch_all` | ✔ | все записи |
| `GET` | `/count/<area>` | ✔ | счётчик новых — бейдж в navbar |
| `POST` | `/verify/<image>/<area>` | ✔ | переключить 0 ↔ 1 |
| `POST` | `/temp_delete/<image>` | ✔ | переключить 0 ↔ 2 |
| `POST` | `/delete_row/<image>` | ✔ | удалить запись безвозвратно |
| `POST` | `/delete_all` | ✔ | вычистить все записи со статусом 2 |

Токен выдаётся на `POST /login` и передаётся в заголовке `Authorization: Bearer <token>`.
Время жизни — 12 часов (`ECOBOT_TOKEN_MAX_AGE`). Истёкший токен приводит к
редиректу на страницу входа: фронтенд обрабатывает 401 в интерцепторе `src/api.js`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest backend/tests -q           # 17 тестов: API, авторизация, SQL-инъекции

cd frontend && npm test           # 2 теста: редирект неавторизованных, рендер панели
```

Бэкенд-тесты работают на временной базе и временном каталоге загрузок, поэтому
не задевают `backend/ecobot.db`. Отдельно проверяется, что инъекция в логин и в
параметр `area` остаётся обычной строкой.

## Конфигурация

Все настройки — через переменные окружения, шаблоны лежат в `backend/.env.example`
и `frontend/.env.example`.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `SECRET_KEY` | `dev-secret-change-me` | подпись токенов, **обязательно сменить** |
| `HOST` / `PORT` | `127.0.0.1` / `5000` | адрес dev-сервера |
| `FLASK_DEBUG` | `0` | режим отладки Flask |
| `DATABASE_PATH` | `backend/ecobot.db` | файл SQLite |
| `UPLOAD_FOLDER` | `backend/media` | каталог для кадров |
| `ECOBOT_TOKEN_MAX_AGE` | `43200` | время жизни токена, сек |
| `REACT_APP_API_URL` | `http://127.0.0.1:5000` | адрес API для фронтенда |
| `ECOBOT_YOLO_MODEL` | `models/yolov8n.pt` | путь к весам детектора |

## Ограничения и планы

Честный список того, что ещё не сделано:

- **Качество модели.** 1000 оригинальных кадров — мало для устойчивой работы на
  новых сценариях (дождь, ночь, частичное перекрытие). Нужен больший датасет,
  разметка от нескольких операторов и валидация на отложенной выборке.
- **Только локальная камера.** Детектор открывает камеру через OpenCV; поток с
  уличных камер по RTSP / VideoStream пока не поддержан.
- **Робот-манипулятор.** `send_to_robot()` — заглушка с выводом в консоль; нужен
  реальный serial-протокол и обработка ошибок связи.
- **Детектор не связан с API автоматически.** Кадр отправляется отдельным агентом
  (скриптом с камеры или оператором). Прямой вызов `POST /add` из детектора —
  логичное следующее улучшение.
- **Нет ролей и прав.** Любой авторизованный оператор может подтверждать и удалять
  detections в рамках своего участка; истории действий нет.
- **Досрочный отзыв токена не реализован** — токен живёт до истечения срока.
  Нужен blacklist или хранение сессий.
- **Dev-стек.** Flask + SQLite рассчитаны на один процесс; для продакшена нужны
  gunicorn/uWSGI, PostgreSQL и объектное хранилище для кадров.
- **Нет пагинации и лимита размера загрузки** — таблица тянет всю выборку.
